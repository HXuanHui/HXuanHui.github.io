# 開發流程
1. 設計架構 & 概念
	* Use Case Diagram　（使用者需求很重要，可是通常院內不會先做需求調查，所以這裡就是規劃好玩的，可以不用做我覺得，除非是完全新的作業，有安排討論）
	* Sequence Diagram （似乎是業界最常用的Diagram，可以很好顯示流程跟判別邏輯。指需要話跨域的物件交互方式就行了。）
	* Activity Graph（懶人就畫這個就好，有大概描述邏輯，快速開發及維護。為補充Sequence Diagram沒有描述的邏輯。）
	* Class Diagram
	* MVC
	* 單一職責原則（SRP）
2. 開寫(於測試環境上)
	* 功能性需求（後端）
	* 功能性需求（前端畫面），不優化、不美化
	* 功能性需求（前端邏輯）
	* 非功能性需求
3. 優化架構
4. unit test測試
5. 實際測試
6. 完成文件&[[README架構]]
7. 維護
	* 查看log
