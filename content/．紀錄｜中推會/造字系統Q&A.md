# 文字編碼的基本概念

- **查看方法**
    
    - **全字庫網站**（[http://www.cns11643.gov.tw）：可查](http://www.cns11643.gov.xn--tw\):-og1gh17h/) Unicode、Big5、CNS 碼。
        
    - **記事本測試**：存成 Big5 或 UTF-8，開啟後檢查是否出現亂碼。
        
    - **程式檢查**：例如 Python `ord('堃')` → 23303 (U+5803)。
        
- **目的**：判斷一個字在 Big5 或 Unicode 中的對應情況，確認是否支援難字或造字。
    

---

## Big5 與其擴充

- **Big5 的歷史**
    
    - 1984 年台灣制定，收錄約 13,000 字。
        
    - 醫院早期資訊系統廣泛採用，因 Unicode 未普及而延續至今。
        
- **問題**
    
    - 字集有限，許多生僻字（如「𨗁」）缺字，導致存取亂碼（顯示「□」）。
        
- **Big5-E 擴展**
    
    - 擴充至 20,000–30,000 字。
        
    - 提供 **使用者造字區**（FA40–FEFE），可透過工具（如 eudcedit）自行定義字形。
        
    - 範例：
        
        - 標準「堃」→ U+5803、Big5 964F。
            
        - 造字版「堃」→ FA5F（Big5-E）、對應 Unicode 私用區 U+E01F。
            

---

## CNS 11643 標準的角色

- **定義**：台灣文字標準，收錄 10 萬+ 字，分為多個「字面」（如 3-3476、第 3 字面）。
    
- **作用**：作為 **Unicode 與 Big5-E 的轉換橋樑**。
    
- **流程**：
    
    - U+5803（堃） → CNS 3-3476 → Big5 964F。
        
    - U+E01F（造字堃） → CNS 16-2140 → Big5-E FA5F。
        
- **必要性**：確保不同編碼間轉換精準，避免醫療紀錄中的字誤或遺失。

## 造字系統與外國人名字

- **造字原理**：
    
    - 缺字時，用造字工具繪製字形並分配 Big5-E 碼。
        
    - 系統將其映射到 Unicode 私用區（PUA）。
        
- **應用範例**：
    
    - 病人姓名中的生僻字。
        
    - 外國人名字：
        
        - 若用拉丁字母（如「John」），Unicode 有收錄。
            
        - 若以特殊音譯或符號顯示，需造字並配置 Big5-E 碼。
            
- **為何仍需 Big5-E**：醫院舊系統多採用 Big5 資料庫，全面轉 Unicode 成本高。
    

---

## 輸入法比較：微軟 vs. 中推會

- **微軟輸入法**
    
    - 支援 Unicode 與全字庫標準字。
        
    - 需額外安裝字型才能顯示特殊字。
        
    - 對院內造字支援不足，跨電腦時可能亂碼。
        
- **中推會輸入法**
    
    - 支援全字庫及院內造字（Big5-E）。
        
    - 內建醫療需求的字碼轉換，跨電腦更穩定。
        
- **差異總結**
    
    - 微軟輸入法：偏重一般標準字，適合一般用途。
        
    - 中推會輸入法：結合醫療造字需求，更符合醫院系統環境。
